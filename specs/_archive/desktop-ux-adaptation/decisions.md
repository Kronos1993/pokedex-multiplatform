## 2026-08-18 — Step 7 — `focusable()`/`onPreviewKeyEvent` was leaking onto Android/iOS, gated it behind `isDesktop`

While preparing manual verification, found that both `AppTopAppBar`'s `topBarModifier` (Step 2) and `PokedexScreen`'s `NavDrawer` modifier (Step 5) attached `.focusRequester(...).focusable().onPreviewKeyEvent{...}` whenever `onRefresh != null` / unconditionally, respectively — gating the *behavior* inside the key-event lambda on `isDesktop`, but not gating whether the modifier chain was attached at all. Net effect: on Android/iOS, every one of the 17 screens (all now pass `onRefresh`) and the Pokedex drawer would have become keyboard-focusable even though no icon/shortcut ever fires there — a real violation of "AppTopAppBar's existing behavior is unchanged on Android/iOS" (AC-1) that a build-green check alone would never catch, since it's a runtime/semantics change, not a compile error. Fixed by moving the `isDesktop` check to the outer `if` that decides whether to build the augmented modifier at all, in both files; re-verified `:androidApp:assembleDebug` and `:shared:compileKotlinJvm` still green after the fix.

## 2026-08-18 — Step 2 — Desktop `F5` refresh shortcut needs the app bar to hold keyboard focus

Compose Multiplatform Desktop key events (`Modifier.onPreviewKeyEvent`) only fire within a subtree that currently has focus — there is no window-level shortcut registration reachable from `AppTopAppBar` alone (that would require a change in `desktopApp/main.kt`, out of this spec's file scope). Chose to have `AppTopAppBar` request focus onto itself via a dedicated `FocusRequester` in a `LaunchedEffect` whenever `onRefresh != null && isDesktop && !isSearching`, so `F5` works as soon as a screen with a refresh action loads, without fighting the existing search-field focus request. Trade-off: the app bar silently holds initial keyboard focus on Desktop screens that have a refresh action — acceptable for this spec's scope, but a true global shortcut (working regardless of what has focus) would need a window-level key listener in `desktopApp/main.kt`, which is a natural follow-up if this proves too narrow in practice.
